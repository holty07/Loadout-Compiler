# M2 — balance harness

Scope: sweep runner (`harness/sweep.gd`), report generator, a generated loadout
matrix (every legal combination at each tier plus a random sample of
mixed-tier builds), a hill-climb search over the matrix, and a deliberately
crude debug renderer — boxes and labels, no design tokens, no polish,
disposable code thrown away at M4. No data-only balance tuning yet — that
is M3.

The debug renderer isn't optional scope-creep: without it, the first moment
anyone can watch this game is M4, which is most of the way through the
build — far too late to discover the core loop is inert. See
`docs/plan.md`'s *Testing points* and *Why the debug renderer exists*.
Budget roughly a day for it and build it knowing it's thrown away; it must
never become a dependency of the real M4 shell.

## Exit criterion

```bash
godot --headless --script harness/sweep.gd -- --matrix harness/loadouts.toml --seeds 2000 --out reports/
```

completes in under two minutes on 8 cores for 50 loadouts × 2,000 seeds, and
commits a report artefact under `reports/` with win rate, clear rate per
depth, time-to-kill spread (p10/p50/p90) per enemy archetype, and
first-choke attribution as a distribution.

The debug renderer has no automated exit criterion of its own — it's a
throwaway tool for the human testing points in `docs/plan.md`, not a tested
deliverable. It just needs to open a recorded run and step through it.
